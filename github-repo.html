Author

Published

August 14, 2026

I recommend you work on understanding the web interface before reading this page. In fact, it is possible to work with PrairieLearn only via the web interface. However, consider the following questions:

  • Will you create hundreds of questions in PrairieLearn?
  • Would you like some of your questions to be significantly more complex than the example question you made via the web interface?
  • Would you like to be able to leverage agentic AI in your question development? That is, are you interested in using prompts like the (abbreviated) examples below:
    • Bulk Generation: Generate 10 questions similar to Lecture 7 examples and add them to a new assessment.
    • Format Conversion: Convert these 5 multiple-choice questions into short-answer questions.
    • Metadata & Tagging: Find all questions discussing topic X and append tag Y to their tag lists.
    • Parameter Randomization: For cleaner math, modify Q1–Q5 to generate single-digit integer values instead of real numbers.
    • Scope Verification: Verify that all questions in this assessment use only concepts covered in Lectures 1 through 8.
    • Bug & Edge-Case Audit: Check all questions in this assessment to ensure random parameters never cause zero-division errors.
    • Randomness Audit: Generate 1000 variants of this question using its current randomization parameters, and ensure all edge cases are handled correctly.
    • Difficulty & Weighting: Identify difficulty outliers in this assessment and critique the assigned point values.
    • Dynamic Explanations: Write step-by-step student feedback (consistent with randomized variables) for wrong answers in this question.

If you answered “yes” to any of the above, I strongly recommend you learn how to work directly with your PrairieLearn GitHub repository (“repo”), as described on this page.

Tools to Install

First, you’ll need to install a few things (if you don’t already have them installed):

  • Git
  • Python

Next, you will need an integrated development environment (IDE). If you’re already familiar with a particular IDE and know how to (1) use the terminal and (2) use agentic workflows with code, then stick with what you know. Otherwise, I recommend using VS Code with an AI extension (e.g., Claude Code).

Note

You can use VS Code for free, but if you want AI assistance with more than minimal usage, you’ll need a subscription. For example, at time of writing, for my usage with PrairieLearn, I find the $20/month Claude Code subscription sufficient and highly useful.

Cloning Your Repo

As briefly mentioned above, your PrairieLearn course (including questions and assessments) is stored in the GitHub repo that you gained access to when your course was created. This basically means that your course is stored “in the cloud”. We need to get a local copy of it; this is called “cloning” the repo. Follow these instructions to clone a repo.

Opening and Exploring Your Repo

Open your Repo in your IDE. For example, if you’re using VS Code, click on “File” in the top menu, then “Open Folder”. Navigate to the folder where you cloned your repo and open it. You should see a list of files and folders in the left-hand panel.

Explore the folder structure a bit, and open the files you see. You should recognize some of the files you saw in the web interface. For example, in the questions folder, there should be a subfolder for each question you created, and inside each of those subfolders are the files that define the question: info.json, question.html, and server.py. Similarly, note the assessments folder contents.

Now, you can edit these files directly in your IDE, and also ask AI to do it for you.

Keeping Everything in Sync

We now have three copies of your course:

  1. The local code (the local repo) on your computer
  2. The remote code in your GitHub repo
  3. The code in the PrairieLearn web interface

This I promise you: if you don’t keep these copies in sync, it will tear up your heart and your happiness will go bye bye bye. The syncing steps depend on how you adjust something for your course:

  • Edit local code (1), push to the remote repo (2), and sync via the web interface (3)
  • Edit via the web interface (3), push to the remote repo (happens automatically) (2), and pull to your local code (1)
Warning

Avoid syncing conflicts: To keep things simple, don’t edit your content both locally and on the web interface between syncs. Rather, pick one place to work at a time and sync before switching.

Details are provided in the subsections below.

If You Edit Your Local Code

When you edit files in your local repo (e.g., with VS Code), you first need to “push” those changes back to the GitHub.com repo so that PrairieLearn can see them. The easiest way to do this is through VS Code’s built-in Source Control panel:

  1. Click the Source Control icon in the left-hand activity bar (it looks like three connected dots and is labeled “Source Control” when you hover over it; it often shows a number badge for changed files).
  2. You’ll see a list of your changed files. Hover over “Changes” and click the “+” icon to stage all of them (or stage individual files the same way).
  3. Type a short message describing what you changed (e.g., “Added new question about linear equations”) in the message box at the top.
  4. Click the blue “Commit” button, then click “Sync Changes” (or “Push”) to send your changes to GitHub.com.

If you prefer the terminal, open a terminal in VS Code (Terminal menu, “New Terminal”) and run these three commands in your repo folder, in order:

git add .
git commit -m "Describe your changes here"
git push

Next, we need to tell the PL web interface to “reload” the course so that it sees the changes we just pushed. Click the “Sync” tab on the left side, and then the blue “Pull from remote git repository” button. When the process completes successfully, your course has been updated! You can verify this by looking at the changed items (e.g., questions, assessments) in the web interface.

If You Edit Via the Web Interface

Similarly, if you make changes to your PrairieLearn course via the web interface, you need to “pull” those changes to your local repo so that your local files are up to date. The first step of this happens automatically: when you make changes in the web interface, those changes are automatically pushed to your GitHub.com repo. Thus, all that remains is to pull those changes to your local repo.

In VS Code, click the Source Control icon in the left-hand activity bar and click the “…” (More Actions) menu at the top, then choose “Pull” (or simply click the sync/refresh icon in the bottom status bar if you see one). Your local files will be updated to match what’s on GitHub.com.

If you prefer the terminal, open a terminal in VS Code and run this command in your repo folder:

git pull

Resources for your Repo

I recommend you download these useful PrairieLearn files and copy them into the root of your PrairieLearn repo. That is, after copying, your repo should have folders called serverFilesCourse and tools at the root (not inside some sub-folder), and your questions folder should have a templates folder inside of it. The templates folder contains several example questions. These templates show you or an AI agent what syntax is needed to create various types of content. You may find it useful to refer to them in any prompts for creating questions.
